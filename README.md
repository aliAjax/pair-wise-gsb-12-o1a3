# 区域限行与替换车派车台

由「车辆调度小工具」扩展而成的区域限行与替换车派车台。

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则冒烟测试：`./node_modules/.bin/esbuild scripts/smoke.ts --bundle --platform=node --format=esm --outfile=/tmp/smoke.mjs && node /tmp/smoke.mjs`

## 功能闭环

### 派单登记（拒绝并保留输入）
登记车牌、司机、工作区域、任务时段、准驾车型与配送路段。审查任一命中即**整单拒绝**：
- 排放等级低于等于规则阈值，且任务时段与限行时段重叠（支持区域/全城、星期、跨天）；
- 车牌尾号命中区域尾号限行；
- **任务结束时**年检已失效（`任务结束日 > 年检有效期`）；
- 司机准驾车型低于车辆核载等级或任务准驾要求；
- 车辆时段被其它任务/预占接管占用；时段不合法或资料不存在。

拒绝时表单输入原样保留，拒单记录列出**车牌、区域、时段、原值和命中规则**，并可一键回填重新提交。

### 替换车接管（接管前原车不释放，接管后继承未完成路段）
1. 「预检并锁定替换车」对候选车/司机走同一套审查，通过后形成**预占**：候选车被预留到任务结束，原车继续占用、不得释放；
2. 「确认接管」后原车仅在接管时刻释放，替换车从接管时刻占用至任务结束，全部**未完成路段**改挂替换车，已完成路段与责任车冻结；
3. 每次接管记录时间、原因、原车→替换车、司机变更与继承的路段，形成接管链；可撤销预占。

### 已完成冻结与修订链
- 全部路段完成后任务才能标记完成，完成后冻结，不可就地修改；
- 调整（含对已完成任务的调整）一律**另建带原因版本**：旧版本标记被替代并冻结，新版本沿用 rootId 递增版本号、继承路段状态；
- 调整审查不通过时生成「被拒绝的调整版本」，原任务不受影响；修订链按版本展示。

### 一致性与组织
- 任务、限行规则、车辆/司机资料、接管记录、修订链统一持久化在 localStorage（key：`dfwlfront-3-dispatch-console`），刷新后一致；顶栏可重置示例数据。
- 代码按职责拆分：
  - `src/domain/`：车辆资料模型、种子数据与**纯审查计算**（`audit.ts`：限行重叠、占用区间 `occupiedIntervals`、整单审查）；
  - `src/store/dispatch.ts`：Pinia 状态机，负责派单、接管两步流程、修订链与持久化；
  - `src/views/` 与 `src/components/`：派单登记、派车台、限行规则、车辆/司机资料四个页面视图及任务卡、命中规则面板。
